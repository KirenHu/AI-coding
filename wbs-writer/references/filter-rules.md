# 信息取舍规则：哪些证据进 WBS

判断标准只有一个：**这件事管理层看了是否关心，能不能对应到项目交付？** 关心的进表，不关心的丢弃。

## 保留

| 证据类型 | 进表方式 |
|---|---|
| 产出或更新了 PRD、原型、线框、方案、调研报告、测试集、清单（claude-mem 的 feature/decision 记录或会话摘要，或文件路径里有 PRD、原型、方案等字样） | 归入对应事项，交付物写产物名和版本 |
| 评审会、管理层会、周会上的**决策**和**行动项**（听记） | 决策写进相关事项的备注；指派给本人的行动项，作为本周新增行 |
| 功能开发完成、联调通过、发布上线、测试通过率 | 事项写开发或测试内容，备注写量化结果 |
| 依赖阻塞、被暂停、优先级调整（听记或群消息） | 状态写暂停或进行中，备注写原因 |
| 已完成的钉钉待办，且与项目相关 | 作为该事项“已完成”的佐证 |
| 本周日程里的评审、发布、汇报节点 | 作为本周新增行或预计完成时间的依据 |
| 群消息里的交付通知、范围确认、外部团队承诺日期 | 写进备注，例如“需平台团队协助，预计0914可以完成” |

## 丢弃

- **工具与环境**：安装或配置 claude-mem、dsh、Codex、MCP，修 hooks，调提示词，跑测试脚本本身。例外：工具建设本身就是项目交付时保留，例如“基于DSH定制化工作台开发”。
- **一次性琐事**：答疑、帮同事看问题、改错别字、导出文件、整理桌面。
- **个人学习**：读文章、看教程、试新模型。只有形成了“调研结论”并用于项目时才保留。
- **过程噪音**：claude-mem 里同一产出的多次中间修改、`discovery` 类“读了某文件”的记录、失败后重试的记录。这类证据最多用于佐证，不单独成行。
- **与本人无关**：听记里别人负责的事项。除非本人是共同负责人，或者这件事是本人工作的依赖。
- **闲聊、通知、广告**：群里的节日问候、行政通知、无关转发。
- **敏感内容**：薪资、绩效、人事、客户合同金额等，一律不进表。

## 归并

1. 先按项目分组（`config.projects`），再按分类分组（`config.categories`，参考上一版表已有的分类）。
2. 指向同一个产物（同一份 PRD 或同一个模块）的证据，合并成一行。
3. 一周内针对同一事项开的多次会，只保留最后一次的结论，日期写最后一次。
4. 合并后某一行仍然没有可验证的产物，又不是规划行，就降级为“待确认”，不进正文。

## 证据可信度（冲突时按此取舍）

听记里的明确决策 > 已完成的钉钉待办 > claude-mem 的 feature/decision 记录 > claude-mem 会话摘要 > 群消息。

AI 听记的摘要可能有误。涉及数字和日期时，优先用逐字稿原文或文件内容核对；核对不了的，在 md 里标“来自听记摘要，未核对原文”。
