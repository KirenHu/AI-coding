# wbs-writer：周度计划表（WBS）撰写

## 产出是什么

每周一运行一次，产出两部分，写进同一张累计表：

1. **回顾上周**：把上周已有的行更新为实际结果，即补全“状态”“交付物/完成标准”“备注”三列。
2. **规划本周**：追加本周事项，以及一行“WeekN 复盘及下周启动会（次周一）”。

输出目录为 `~/WBS/<YYYY>-W<ww>/`（ISO 周，取运行当天所在周），文件只留在本地：

- `周度计划表-<姓名>-W<ww>.xlsx`：累计表，即上一版全部行，加上更新后的上周行，再加上本周新增行。
- `WBS-<姓名>-W<ww>.md`：本周新增和改动的行，每行附证据来源；“待确认”清单放在最前面。

**`~/WBS/` 是本人所有 WBS 的唯一存放处**：每周一个 `<YYYY>-W<ww>/` 目录，历史 WBS 在安装时已归集进来。本人确认修改后的版本也保存在同一周目录里。写本周 WBS 前，先看上一周目录中最新修改的文件，以它为主线。

写作规范见 `references/style-guide.md`，信息取舍见 `references/filter-rules.md`。**动笔前必须读完这两份文件。**

## 前置条件

- 配置文件 `~/WBS/config.json` 已存在，由 `prompts/setup.md` 生成。字段如下：
  ```json
  {"name":"张三","projects":["智能问数"],"categories":["智能问数一期开发","智能决策"],
   "week1_start":"2026-08-17","baseline_wbs":"/path/周度计划表.xlsx",
   "plan_sources":["~/Documents/某项目/outputs/wbs-*/*.xlsx"],
   "project_map":{"新一代AI协作平台":"SOP平台"},
   "chat_groups":[{"name":"智能问数项目群","openConversationId":"cid..."}],
   "mem_projects":[]}
  ```
  - `plan_sources`：本人自己写的计划文件（任意表格格式）的路径通配，取最新一份作为“上一版计划”。**这是 WBS 的主线，没有它生成结果会偏离实际。**
  - `project_map`：claude-mem 按文件夹记项目，用它把文件夹名映射成业务项目名。
  - `baseline_wbs`、`chat_groups`、`mem_projects`（只采集这些 claude-mem 项目，留空表示全部）可以留空。
- claude-mem 已安装，并在后台持续记录。`collect.py` 以只读方式直接读取 `~/.claude-mem/claude-mem.db`，不依赖 worker 是否在线。worker 只负责记录；它没有运行时，会导致上周的记录缺失。
- Python 能 `import openpyxl`。不能导入时，执行 `python3 -m pip install --user openpyxl`。
- `dws` 已登录：`dws contact +me --format json` 能返回本人信息。

## 流程

### 1. 定周次（用脚本算，不要心算）
```bash
python3 <skill目录>/scripts/collect.py --plan-only
```
脚本输出 JSON：`run_date`、`iso_week`，`last_week`（上周一至周五的日期范围及 WeekN 标签），`this_week`（本周的日期范围及 WeekN 标签），`prev_wbs`（找到的上一版表路径）。

WeekN 的取法：上一版表最后一个周期是 WeekK，本周就写 Week(K+1)。没有上一版表时，按 `week1_start` 计算。

### 2. 收集证据
```bash
python3 <skill目录>/scripts/collect.py --out ~/WBS/<YYYY>-W<ww>/evidence.md
```
`evidence.md` 按来源分节，每条证据带一个 `[E编号]`。来源和时间窗口如下：

- claude-mem：上周一 00:00 到本次运行时刻之间的记录。只保留 `feature`、`decision` 类 observation，以及每个会话最后一条 session summary（概括该会话做成了什么）；change、bugfix、discovery 等过程记录由脚本丢弃，只计数。
- 钉钉听记：同一时间窗内的会议摘要、关键决策和行动项。
- 钉钉待办：本人相关的待办，包括已完成、新建和逾期的。
- 钉钉日程：上周的日程和本周已排的日程。
- 项目群消息：只读 `chat_groups` 里配置的群，取同一时间窗。

### 3. 以上一版计划为主线
evidence.md 的“上一版计划”一节是本人亲手写的计划，项目名、模块名、工作内容以它为准：
- 上一版计划里本周要做的每一项，都要出现在本周 WBS 中，用其他证据判断进展（已完成 / 进行中 / 未动）。
- 其他证据里出现、但上一版计划没有的重要成果，才作为新增行。
- 不要用 claude-mem 的文件夹名或自己概括的名称替换本人的叫法。
- 上一版计划的一行对应 WBS 的一行，不合并、不拆分；状态不同的子项（如“功能定义已完成、原型设计进行中”）分成两行。
- “分类”列填本人计划里的“工作模块”名；项目名只有一个时不写进分类，多个项目时写成“项目/模块”。
- 上一版计划里的“优先级”（P0/P1）写进备注首条，例如“P0”。

### 4. 过滤与归并
按 `references/filter-rules.md` 逐条判断证据：保留的归到“项目 → 分类 → 事项”，丢弃的不进表。

同一产出的多条证据合并成一行。例如 6 条修改 PRD 的 observation 只写一行“完成××PRD v0.3”。

### 5. 写行
按 `references/style-guide.md` 写 8 列内容。规则如下：

- 上周行：凡是上一版表里属于上周的行，**全部要处理**，不许删除，也不许改动“事项”文字。
  - 有证据：状态改为已完成（写明交付物）、进行中或暂停（写明原因或卡点）。
  - 没有证据：状态和备注都保持原值，只在 md 的待确认清单里提问（xlsx 不出现“待确认”字样）。这类行不需要证据编号。
  - “待确认”不是状态值，xlsx 的状态列只能填四种状态。
- 本周行：来源有四处。上一版计划中本周要做的每一项（即使还没有开工证据）；上周“进行中/暂停”的延续项；听记和待办里本周要做的事；日程里已排的评审或交付节点。新增行的状态是“待开始”，已经开工的写“进行中”。
- 每个业务行必须至少挂一个证据编号，写在 md 里，xlsx 不写证据编号。没有证据就不写这一行；本人确实应该做的事，放进 md 的“待确认”清单。
- 复盘会行是制度性固定行，不需要证据：周期取本周，分类 `WeekN 复盘及下周启动会（次周一）`，事项 `汇总本期方案、产品设计、开发进度`，负责人本人，预计完成时间为次周一，状态 `待开始`，交付物 `计划表`，备注留空（下周回顾时再填会上确认的事项）。
- 预计完成时间：已完成的事项填证据里的实际完成日；未完成的，证据里有承诺日期就用它；没有时填本周五，并在 md 待确认清单问一句“<事项>完成日默认周五，可以吗？”。不要留空。
- 行数：业务行通常 2～5 行，加复盘会行。证据只够写 1～2 行时，就只写这么多，不要为凑数拆行或编造。

### 6. 生成文件
先把行写成 `rows.json`（结构见 `scripts/render_xlsx.py --help`），然后执行：
```bash
python3 <skill目录>/scripts/render_xlsx.py --rows ~/WBS/<周>/rows.json --base <prev_wbs或空> --out-dir ~/WBS/<周>/
```
脚本会沿用上一版表的样式；没有上一版表时，使用 `templates/周度计划表模板.xlsx`。目标文件已存在时，自动另存为 `-v2`、`-v3`。

### 7. 自检后交付
逐条对照 `references/style-guide.md` 末尾的“自检清单”。有不合格的行，改完重新生成。

最后向用户报告：文件路径、上周行数和本周行数、待确认条数，以及证据缺口（例如听记拉取失败）。

## 失败分支（遇到就按此处理，不要跳过、不要编）

| 情况 | 处理 | 仍失败 |
|---|---|---|
| `config.json` 不存在 | 停止，提示先运行 `prompts/setup.md` | — |
| claude-mem 数据库不存在，或时间窗内没有记录 | evidence.md 顶部会标出缺口，只用钉钉证据继续 | md 顶部写“缺 AI 工作记录，请确认 claude-mem 是否在后台运行” |
| dws 未登录或命令失败 | 在 md 顶部写明哪个来源失败及报错首行，其余来源继续 | 所有钉钉来源都失败时，在 md 顶部标“缺会议与待办证据”，上周行状态保持原值，本周只写有 claude-mem 证据的行 |
| 找不到上一版表 | 从模板新建，只写本周行，并在 md 中注明“首次生成，无上周回顾” | — |
| 本周证据少于 3 条 | 仍然生成，在 md 顶部提示“证据不足，请重点人工补充” | — |
| `render_xlsx.py` 报错 | 读报错信息，修正 `rows.json` 的结构后重跑 | 重跑后仍报错，只交付 md 和 `rows.json`，并报告错误原文 |

## 禁止事项（无人值守运行时同样适用）

- 不发送任何消息、邮件、钉钉待办或日程，不写钉钉文档或表格。WBS 由本人确认后自己发送。
- 不修改 `baseline_wbs` 原文件，也不覆盖 `~/WBS` 里已有的文件。只新建文件。
- 不执行 `git push`、`git reset --hard`、`rm -rf`，不删除 `~/WBS` 下的任何内容。
- 不凭印象编造交付物、版本号、测试数字或日期。所有数字都必须能在证据里找到原文。
- 不把别人的工作写成本人的。只有在证据显示本人是负责人或共同负责人时，负责人一栏才写本人。
- 不把以下内容写进表：调试工具、安装 claude-mem 或 dsh、个人学习、闲聊、一次性答疑（详见 filter-rules）。

## 反例（看到自己写成这样就重写）

| 坏 | 好 | 问题 |
|---|---|---|
| 事项：研究了一下本体论 | 事项：开展本体论调研，判断是否及如何调整后台设计；交付物：调研文档0.1版 | 只写了活动，没写目标和产物 |
| 交付物：已完成 | 交付物：后台PRD v0.64、线框 v0.14 | 交付物不能被验证 |
| 备注：进展顺利，继续努力 | 备注：开发测试 120/120，下周重点为回答准确性修复 | 备注写的是空话 |
| 状态：暂停（无备注） | 状态：暂停；备注：语义层依赖 | 暂停没有写原因 |
| 一周列 12 行，每次会议各占一行 | 3～6 行，会议的结论并入对应事项的备注 | 颗粒度过细 |
| 事项：配置 Codex hooks、修 dsh 报错 | （删除） | 工具折腾不进表 |

## 让 skill 持续进化

测试集在 `evals/test-prompts.json`，格式符合 darwin-skill 的要求。用户说“优化 wbs-writer”时，在本 skill 所在的 git 仓库里调用 darwin-skill，每轮只改一个维度，每轮结束都要停在 checkpoint 等用户确认。

每周本人修改过的 WBS 是最好的训练样本。用户确认后，把“生成版本和确认版本”的差异，按 `{"prompt","expected"}` 的格式追加进 `evals/test-prompts.json`。
