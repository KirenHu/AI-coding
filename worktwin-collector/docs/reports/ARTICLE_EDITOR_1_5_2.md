## 真实模型的新案例

运行 `scripts/evaluate_article_editor.py`，使用虚构商城数据与现有模型连接，在独立测试数据库执行，未读取真实私人来源。完整候选与审校结果见 [JSON](article-editor-synthetic-1.5.2.json)。

| 验证点 | 观察到的结果 |
|---|---|
| 同项目的退款业务与生产部署 | 生成 2 篇独立文章，没有强制合成项目大文档 |
| 退款定义、申请材料、审批与异常处理 | 合成同篇退款流程，没有一条信息一个页面 |
| 正式确认从两人审批改成一人审批 | 维护原文章 ID 4，版本 1 → 2 |
| 后导入但业务时间更早的会议 | 没有把现行一人审批改回旧两人审批 |
| 最新讨论提出免审批，但尚未确认 | 没有把建议写成已生效规则 |
| 原文仍有效的特殊退款、核对支付、原路退回、不重复退款 | 更新后继续保留 |
| 无关部署手册 | ID 5、版本 1、正文保持不变 |
| 处理回执 | 6 条材料在文章发布后消费；最终仍是 2 篇文章 |

已人工阅读这组模型结果；未人为修改其文章后再计为通过。这是一个含两个独立事项和三类冲突输入的实际样例，不是跨行业准确率，也不证明任意项目都能可靠自动归属。真实历史资料没有批量重跑，本次不把历史人工修订成果算作模型能力。

本轮的新编辑与审校机制接入文件/会话文章管线。浏览器操作文章继续使用原管线，需单独按任务事件证据评测，不能用本报告替代其质量验收。
