# 网站白名单与持续采集

浏览器插件 0.4.0 与本次 Collector 一起使用。更新插件后沿用配对；旧版本的历史记录、摘要、网站操作手册继续可读。

## 本次行为

- 网站按精确 Origin 保存，协议、域名和非默认端口均参与匹配。添加时默认关闭；HTTPS 的 443、HTTP 的 80 归一化。HTTP 仅接受本机 localhost / 127.0.0.1。
- 人工打开网站后持续记录全部匹配且已经获得浏览器权限的标签。离站、关闭标签、应用重启只结束当前记录区间，开启意图保留；再次访问时创建新记录区间，不补采中断期间的操作。
- 有效的签名平台请求也能开启网站。人工关闭网站会停止该站当前所有请求；旧请求的重试、轮询不会重开，新签名启动可以再次申请。平台完成只释放自己的请求。
- 总开关关闭时停止实际采集，保留站点意图、插件配对和 AI 授权。解除配对是独立操作。恢复总开关后，原平台任务须先查询到新的有效状态才能恢复。
- 人工采集与平台任务共用同一文档监听。人工开启期间的原始事件只存一份，任务通过引用取得属于其绑定标签、文档、页面和有效时间内的事件。同站其他标签的人工浏览不会进入任务记录。
- 普通 DOM 弹窗、同源 iframe、`srcdoc`、开放的 Shadow DOM 沿用脱敏采集。跨源 iframe 不采集。表单输入值、密码、页面全文和截图不采集。
- 网站操作手册使用已结束的人工记录区间增量更新；平台专属事件不会自动进入知识库。旧的单次手动采集 API 保留用于兼容，但新版界面和插件使用站点开关。

## 本机 API

页面接口使用本地用户令牌，插件接口使用已有配对凭据。

| 接口 | 用途 |
| --- | --- |
| `GET /api/browser-capture/sites` | 白名单及人工意图、平台请求数、实际状态 |
| `POST /api/browser-capture/sites`，`{url}` | 添加网站，默认关闭 |
| `PUT /api/browser-capture/sites/{id}`，`{enabled}` | 开关网站；关闭同时停止当前平台请求 |
| `DELETE /api/browser-capture/sites/{id}` | 移除白名单，保留历史 |
| `POST /api/browser-capture/unpair` | 解除配对，保留站点意图 |
| `POST /capture/sites/current` | 插件读取总开关和白名单 |
| `POST /capture/sites/bind` | 为匹配且获权的文档建立记录区间 |
| `POST /capture/sites/event` | 保存脱敏事件及任务引用 |
| `POST /capture/sites/close` | 结束记录区间，不关闭站点意图 |

## 平台协议的真实边界

现有平台接入仍为 v1：环境变量指定可信平台及签名密钥，平台签名 `start` / `complete` 命令，Collector 查询同站状态接口。签名目标只授权首文档；离开或刷新该文档结束该次任务采集。新的网站持续开关不会把 v1 任务扩大为整个站点。

需求中的 SOP v2 尚未实现：配置包、`attempt_id`、`start_request_id` 幂等协商、多页面任务授权、暂停/恢复、整批报告编辑与版本回传、平台回执和重试。上线这些能力需要先确认平台两侧契约并联调。当前 UI 不伪造平台业务完成，也不显示未经回执确认的“已回传”。

## 验证

`tests/test_browser_sites.py` 覆盖 Origin、持续意图、总开关与配对、关站抑制、任务完成、事件引用隔离及本地接口权限。原有浏览器采集与摘要测试保持通过。

`scripts/ui_browser_extension_acceptance.py` 使用临时数据库、随机本地端口、临时 Chromium 配置及合成 HTTPS 页面。任何写请求之前，核验该测试子进程的随机身份、数据库路径和版本。真实 MV3 扩展覆盖签名任务、普通弹窗、iframe、Shadow DOM、持续站点导航、总暂停/恢复及手册生成；不访问或提交真实业务页面。
