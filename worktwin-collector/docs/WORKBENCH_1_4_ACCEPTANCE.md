# WorkTwin 1.4.0 工作台改版

本次在 PR #26 的 1.3.1 基线 `5d8b8fd9` 上实现已确认的工作台交互。当前应用代码为 1.4.1 测试候选，浏览器插件为 0.4.1。

## 1.4.1 实际使用修正

- 应用升级后旧解压插件不会自行升级。心跳上报插件版本和 Chrome 网站权限，工作台显示升级提示及待授权网站；已有配对与采集开关继续沿用。
- 分身只授予文章，项目/来源是批量文章范围，文章选择是补充范围。材料保持在待整理入口，不能新授予，也不由旧 pin 越过文章边界。文章的当前原文片段参与本地问答、`search_article_sources` MCP 和已获分享许可的发布快照。整份混合日志仍走原来的完整日志能力。
- 文件夹标题为目录名，添加流程不再要求额外命名。
- 旧项目判断仅接受引文中的项目名或显式连续上下文，导致没有项目名的跨文件事项退回每份资料的 session 范围。新的项目路由输入包含目录、资料开头、文件时间、最近三份同来源且已授权的资料，以及已有项目。模型先提出业务项目名称与目标，判断模型匹配已有身份或决定建立新项目；判断结果和来源上下文随工作单元保留。同目录不同业务目标可以建立不同项目。
- 归并提示按完整事项组织定义、步骤、规则、异常，不将这些子主题逐个成文。目录或时间接近不会直接合并，项目路由仍不创建分身授权。

回归涵盖没有重复项目名的跨文件归属、同目录不同目标、资料授权隔离、暂停采集后的关系保留、材料授权拒绝、原文片段问答/分享、旧插件版本提示与网站权限状态。已有资料不会因升级而触发全量模型处理。

## 已实现

| 路径 | 实际行为 |
| --- | --- |
| 知识库 | 主列表为主题文章；材料从“待整理”进入，保留状态、项目、类型、搜索、更新建议、停用、归档、导出。 |
| 知识详情 | 抽屉标题为知识名，正文独立，状态与类型紧凑排列；右上日志提供版本查看及回退；原始资料和关联知识仍可访问。 |
| 知识整理 | 提取后先合并同批主题材料，跨批先定位文章再读取完整正文合成；保留文章 ID、版本及每个材料引用。不同范围、未决冲突及来源许可继续限制合并。 |
| 分身 | 四个页签管理知识授权、连续试问、分享与访问、基本信息。保留动态范围授权和逐条选择，移除排除编辑。连续追问使用前文，范围/版本变更不复用旧上下文。 |
| 文件夹 | 原生目录选择器；采集、AI、分享分别控制，支持查看异常和重试。 |
| 编程助手 | 固定工具整体勾选，格式识别后采集；尚无记录可以勾选等待。Codex 使用其配置目录下 sessions，Claude Code 使用 projects；Cursor CLI 仅识别 `~/.cursor` 下的 JSONL 导出，不读取 IDE 数据库。 |
| 浏览器记录 | 精确 Origin 白名单、逐站持续开关、任务/网站历史分页、插件设置分组。普通 DOM、同源 iframe/srcdoc、开放 Shadow DOM 延续支持。 |
| 模型设置 | 主模型旁配置决策与路由模型。当前专用模型用于项目身份判定；正文整理与问答使用主模型。 |

## 数据升级

- 旧生成知识没有证明“完成文章整理”的持久标记，因此进入材料入口；不按字数、Markdown 标题猜测，不改变其 ID、正文、状态、历史、证据或有效授权。人工内容仍作为文章。收到完整新版本或用户编辑正文后可沿用 ID 转成文章。
- 旧助手来源恰好覆盖标准工具根时沿用；局部目录保留记录和原权限，暂停增量，不把局部授权自动扩大。用户整体勾选只开放采集，AI 和分享分别授权。
- 有排除规则的分身迁移为当时有效知识的逐条名单，删除旧动态及排除规则；没有排除规则的分身沿用原模式。迁移不自动增加新知识授权。
- 暂停来源只停止采集，不撤销历史知识。撤销 AI、分享或移除来源仍按对应操作生效。
- 1.3.x 数据库在首次升级前备份为 `.pre-1.4.0.sqlite`；更早版本仍保留原 `.pre-1.3.0.sqlite` 恢复点。升级不排全量模型任务。

## 验证方式

Python 行为测试使用临时数据库及合成内容，覆盖文章归并、长文完整输入、引用与历史、助手勾选、迁移、授权、连续对话、站点意图与任务隔离。长文回答覆盖文章尾部检索；同一对话显式切换项目以最新问题为准。

现有文件采集、编辑、授权、刷新、更新建议、分享、设置、短窗口布局、MCP 验收保留；新增交互验收覆盖超过十轮的连续问答、授权更新重开会话、发送中切换分身、网站开关与插件分组。浏览器测试使用临时应用/浏览器配置和合成页面。MV3 测试绑定随机端口，并在任何写请求前核验测试进程身份、数据库路径和版本。

HTTP 端到端、分身契约、80 文件增量基准和 Python wheel/sdist 构建同时验收；CI 继续构建 macOS 双架构和 Windows 候选包。实际通过的提交和 CI 链接以 PR 检查结果为准。

## 尚未完成

- SOP v2 的配置包、处理批次、跨页面任务授权、报告编辑与回传回执尚未实现。当前仍使用原 v1 平台签名协议；白名单持续采集不会扩大原任务的页面权限。详见 [浏览器实现边界](BROWSER_CONTINUOUS_CAPTURE.md)。
- 同一物理文件被旧局部来源和新工具整体范围重复覆盖时，仍可能各自索引与整理。完整去重需要将物理索引与证据贡献来源分离；本次没有移动 `source_id` 或复制授权来掩盖重复。
- 模型归并效果只通过合成模型协议和行为测试；未调用用户真实模型、未批量重处理私人资料。真实中文长文的完整性和额外归并调用成本仍需实际样本验证。

本次代码交付不包含安装到本机、清空历史数据库、合并 main 或正式发布。
