# WorkTwin 一期边界

更新：2026-10-10。此文件是产品范围的准则；描述目标不等于功能已交付，实际状态见下表。

## 产品定位

WorkTwin 是持续在后台运行的本地知识整理工具。用户授权少量数据来源，程序检测新增与修改，把工作过程整理为连贯的知识库，供其他 AI 通过 MCP 快速使用。

用户日常仍使用自己的浏览器、文件管理器、Codex 和 Claude Code，不需要迁移到 WorkTwin 内工作。界面主要用于授权来源、查阅或纠正知识、处理不确定事项、配置模型及 MCP 接入。无需维护邮箱、日历、任务系统或另一个聊天助理。

## 浏览器任务采集的独立边界

- 浏览器采集是与文件和 Codex/Claude Code 并列的用户手动开启能力，默认关闭；不因安装插件而开启，也不因为网页浏览动作自动启动。
- 可信流程平台的签名任务票据动态指定精确 HTTPS 初始页面、任务 ID、员工身份和有效期。网站访问权限仍由浏览器/组织管理，不由流程平台绕过浏览器安全提示。用户无需逐个维护目标网站白名单。
- 原业务链接照常打开，不通过 WorkTwin 或插件中转。插件只将该次点击对应的新导航与会话绑定；跳转后的网页不再观察，原始网页跳转行为留记录；任务完成需要平台另发签名信号。失联任务有安全到期限制。
- 插件安装在 WorkTwin 内引导，连接状态依赖真实心跳，不声称跨平台准确识别操作系统默认浏览器的所有扩展安装状态。
- 浏览器操作存独立 SQLite 事件及步骤，和文件 SHA 扫描解耦。表单输入值、原始 DOM、密码和视频不采集；页面提示不等于业务已完成。用户另行授权 AI 分析后，仅发送步骤；结果仍是未验收的临时总结，不自动用于分身或知识发布。

## 知识整理的必要约束

- 业务项目与目录分别记录。一个项目可以跨目录、跨工具；一个目录或会话也可能包含多个项目。目录名不直接决定业务归属。同名项目也不自动合并：用户显式选择已确认项目才能复用其项目身份；创建新项目总会产生独立身份。
- 项目判断优先采用用户明确的项目与目标，结合会话关系、相关资料、仓库和操作记录。时间接近、名称相同或语义相似只能辅助判断，不能单独决定合并。
- 无法确认业务项目的会话和文件，先限制在单份资料；不得凭目录名把其他文件合并，也不得自动当成全局规则。旧版由目录名形成的未经确认项目关联在升级时改为单份资料范围，暂停仍沿用旧推断项目身份的来源知识（包括只编辑了正文、但没有核对范围的知识）。跨会话自动识别仍待实现。
- 分析输入应包含当前工作目标、相关双向讨论、实际事件时间、文件与操作线索、已有主题的当前版本、适用范围及来源。工具事件是独立角色，不能归到前后相邻的用户或 AI 发言中；进程退出码为 0 也不是成果验收，通过与否只按实际证据判断。分批处理需保留前后文，不逐条孤立分析用户消息。
- “同意”必须能够对应此前明确的方案。AI 建议、用户确认、AI 报告完成、工具执行依据和用户验收分别记录。单纯“完成了”不能证明成果已验证。
- 同项目、同主题、同适用范围的内容优先更新已有文章，保留理由、例外、未决问题与来源。当前笔记只保留最新有效结论；被替代正文只存在版本历史或更新日志，不另建为有效知识，也不继续混入当前正文。不同主题、不同权限或未解决的矛盾不直接合并。
- 依据事件发生时间判断先后；扫描、导入和文件修改时间不能替代决策时间。新出现的建议也不能仅因更晚而推翻用户已确认的结论。
- “用户倾向于第二点”、无对象的泛泛评价、临时回应等不进入供 AI 使用的知识。条目必须能够说明未来可用于回答什么工作问题。
- 术语区分：被替代版本属于历史记录；早期程序提炼但范围、价值尚未核实的结果属于待核对资料，两者不能统称“旧知识”。待核对结果保留供复核，暂停用于回答与发布。它们不能因升级自动变成有效知识。
- 原始日志保留为依据；知识库保存可复用内容。MCP 默认检索当前有效知识，需要追溯时再读取允许提供的依据，不能把所有历史讨论直接塞入上下文。

## 交互与验收

知识组织参考 Obsidian：以可独立阅读和编辑的 Markdown 笔记为主体，用双向链接表达主题关系，用少量属性表示项目、主题、适用范围、状态和来源。项目与主题提供导航，不要求用户先设计严密的文件夹层级。来源日志与主题笔记分开，同一主题持续维护当前内容与历史。关系图作为后续辅助视图，不代替笔记正文与证据，也不负责决定权限和项目归属。

Obsidian 只作为部分优秀思路的参考，不以复刻界面、直接接入或双向同步为目标。一期继续使用现有存储与编辑方式，保留已有 Markdown 导出。MCP 按需读取当前笔记、范围和必要引用。

设置固定在主导航底部，长列表由内容区滚动，小窗口下仍可直接点击。条目展示主题、所属范围、适用条件、有效状态与来源；用户可以修改、停用、查看历史。日常采集和整理在后台运行，状态区分排队、处理中、失败和待核对。

用户已确认：通过真实资料验收后，无冲突的新增和补充自动生效；改变已有结论、项目不明或出现矛盾时提醒核对。验收记录绑定模型和整理规则，记录不完整或模型改变时停止自动生效。项目必须经确认；只有原文依据、归因和质量均通过的新增才可自动生效。纯补充必须原样保留当前正文，模型重写或修改条件仍作为待核对提案。当前有限真实样本验证不等于整份本地资料库验收，默认不启用自动生效。

MCP 直接沿用数字分身已保存的知识授权，不复制一套权限。每个分身可生成、更新或关闭独立连接凭据；每次读取都检查当前授权和知识有效状态。只提供项目列表、检索、当前笔记和必要引用，不提供知识修改能力。完整日志默认关闭，需在分身配置中单独授权，且仅限当前授权知识引用的来源资料。撤权、停用、删除分身或关闭 MCP 立即停止读取。

验收必须覆盖：设置在长列表下可见；局部英文提示词要求不能成为所有项目的规则；同主题更新保持原文档编号与历史；冲突未解决时不混入有效知识；未授权来源不进入分析；其他 AI 经 MCP 能读取对应项目的当前知识。完整日志归属、真实资料质量和打包客户端接入尚未通过时，不能宣称一期核心闭环已经完成。

## 个人与企业配置

个人自行配置模型地址、模型与 Key。企业统一分配模型，员工使用企业 Token，不接触供应商 Key。两者共用采集与知识整理逻辑，数据使用与分享遵守来源授权。

现有“数字分身”、远程分享和企业管理员功能保留兼容，但不再作为此次核心范围扩建。是否收敛入口应围绕 MCP 访问与知识授权设计，不继续追加秘书能力。

Apple 签名、公证与自动升级不影响上述能力定义。合成资料和模拟模型测试不代表真实知识质量已通过验收。
