# 1.5.0 文章维护实现与验收

采集器记录文件变化及可见会话。提取器保存信息材料、引用与背景，项目路由根据持续目标及所在目录等线索建立工作归属。材料不直接进入知识库或数字分身文章选择。

独立 ArticleMaintainer 定期取有效、已授权且尚未处理的材料，先规划完整事项的文章主题，再读取相关原文和已有文章。正文可以重写、去重和调整结构；事项无法独立解释时保留材料。一次共享材料未完成全部选题时保留待处理状态。仅新材料影响的文章会更新。

文章单独保存 article_summary 与 change_summary，知识历史保存这些字段及原正文。多个旧分篇合并时保留主 ID、旧版本、引用、原始部分及既有文章授权；已失效的旧引用退出当前依据。项目背景用于选题，具体正文只从选定文章的来源编写，避免引入没有关联来源的业务事实。

浏览器路线独立保存观察，按操作事项编写。网站只是来源边界，部分观察不代表完整业务流程；不会将页面成功提示当后台业务验收。浏览器文章按事件关联可追溯来源，不显示输入值。

原型框架沿用已有工作台。详情页依次为标题与辅助信息、概要、更新表、正文、依据。待整理材料在后台；冲突、历史回退、来源查看及数字分身连续对话保留。来源页完成提示同时等待提取与文章维护。

验收覆盖两阶段处理、待补资料、跨资料同主题更新、只更新相关主题、全文结构改写、合并来源与权限、版本保存、来源替换、授权撤销、重试、共享材料、项目背景隐私、原生打包、连续对话和真实 MV3 事件。合成模型测试验证处理契约；本机历史资料副本用于真实模型阅读与归并检查。

历史重整脚本 rebuild_article_snapshot.py 只在独立备份操作，一次性读取范围限定为既有文章的来源文档，项目背景与相邻资料也遵守该范围，不修改来源开关。apply_article_snapshot.py 在应用停止后应用文章结果，重映射新 ID 并保留活跃原始采集数据、来源与授权开关；人工编辑或来源内容变化不会被覆盖。同步材料处理进度，避免同批内容重复整理；--receipts-only 仅补写已有文章的处理进度，不迁移或修改正文。

任务页同时显示提取和文章维护的排队、运行与失败状态；文章失败达到自动重试上限后可手动重试。macOS 模型凭据在服务器启动后读取，钥匙串权限提示不会阻塞文章阅读；等待期间显示实际状态。

## 更新前筛选与增量处理（2026-10-13）

这轮复用 Collector 的文件 SHA-256、会话事件水位、知识证据和文章维护指纹，不新增向量库或独立调度系统。未发现仓库范围内额外的 AGENTS.md。改动仅作用于后续同步与处理，不扫描或重跑已有生产数据。

### 判断与处理

- 同一文件字节哈希不变：同步文件时间和大小，记录 `raw_hash_equal`，不新增模型任务。正常轮询中时间和大小也未变的文件沿用原有快速路径，不为每次轮询追加日志。
- 以**上次成功提取的完整正文**为比较基准，而不是上次扫描结果。一次模型处理期间多次修改、失败重试或任务被新版本替代，都不提前推进基准。
- 正文完全相同：`exact_content`。保守归一化后相同：`format_only`。归一化只统一 CRLF 与 LF、忽略文末空行；不合并内部空格、段落、缩进、Markdown 行尾双空格，不改数字、日期、否定词或链接目标。引用无法重新定位时仍全文提取。
- 增量仅用于现有文档末尾新增有明确 Markdown 标题的章节：发送完整开篇章节、末尾相邻章节及全部新增内容。开篇与相邻章节提供目标、约束和指代背景。出现撤回、替代、前文引用、代码围栏、章节边界不足或上下文没有明显缩小时，全文处理。
- 改写、删除、数字/日期变化、否定反转、段落移动以及无法可靠对齐均全文处理。首次导入及没有成功基准的历史资料也全文处理。行级差异、旧版本哈希、新版本哈希及资料 ID 留在处理记录中；不会把正文缺席误当作删除。
- 只对同一资料版本去重，不跨来源共享提取缓存。同样的文字可能具有不同项目背景或权限，其他路径/来源首次导入仍独立处理。
- 格式重复仍写入最新正文、元数据、索引和证据关联，并同步当前文章引用版本及已消费材料指纹。AI 授权仍使用原有来源开关，不自动更改。

### 删除和撤回不依赖“提取到新材料”

实质内容变化会把关联文章标为待核对，并加入来源更新队列。正常新材料整理优先处理；已完成全文校正的文章移出队列，避免额外再写一次。即使删除后没有新材料，队列也能让文章维护器读取剩余的完整原文并审校。未核对成功前，旧文章不能作为已确认知识使用。全部来源消失时沿用现有孤立知识清理。

全文重提取后，未被重新确认的旧材料证据退出当前材料集合。引用原句还在、但上下文改变了材料解释时，也更新材料正文和版本。文章编辑提示词明确：旧文章和旧材料不是事实依据；必须以当前完整原文核对删除、撤回和跨段否定。

### 记录、配置和回退

- `knowledge_processing_runs`：每次筛选的模式、原因、版本、差异行范围、状态、正文字符数、选中字符数、提取调用次数及处理耗时。字符数不是 Token 数，也不含全部系统提示和文章整理输入。
- `model_call_metrics`：主模型和独立决策服务的调用次数、失败、耗时及供应商实际返回的输入/输出 Token。并行请求各自记录，不共享最后一次响应状态。没有返回用量时为 NULL，不能视为零。费用不估算。
- `GET /api/processing/stats`：使用现有本机授权，返回累计筛选原因和模型统计，不返回正文、密钥或会话内容。`extraction_calls` 只指提取调用；`models.calls` 包括经过运行时的文章维护、回答、路由等调用。
- 默认启用文档增量。启动环境变量 `WORKTWIN_DOCUMENT_INCREMENTAL=0` 关闭新增章节增量，回到完整提取；已有 `document_incremental_enabled` 设置优先于环境变量。确定性重复判断、来源同步和引用校验继续生效。
- 筛选异常记录 `filter_error` 并使用完整正文；增量引用无法对应原文时记录 `incremental_evidence_misaligned` 并全文重试。模型失败沿用现有重试机制，基准只在成功提交时更新。
- 本地 Embeddings 未引入，也没有语义相似度跳过。因此暂不需要语义影子模式；以后确有证据表明值得接入，再先做影子对照。

### 已验证与边界

2026-10-13：全套离线测试 **334 项通过**。本轮增加 23 项参数化/集成用例，覆盖完全重复、换行格式变化、改写、新增观点、数字和日期变化、否定反转、链接修改、缩进、段落移动、删除后零材料仍刷新文章、筛选异常、模型失败、连续扫描、在途修改、授权关闭、材料重新确认和统计接口。

代表性构造样例：36,082 字符的 Markdown 文档在末尾新增独立章节，选中的正文和上下文为 73 字符；用相同离线模型替身执行提取入口，全文路径调用 4 次、增量路径调用 1 次。包含基础提取提示的输入字符数分别为 50,186 和 1,799。这个对照不包含项目路由、工作上下文补充和后续文章维护，不能外推为整条链路的节省比例。格式重复集成测试的新增模型调用为 0，来源和当前证据仍保留。

尚未验证真实模型的知识召回率、文章事实质量、实际 Token/费用节省及长期运行收益；离线模型替身验证的是流程与证据管理，不是模型理解能力。本轮没有对私人历史会话发起新模型请求，没有安装替换本机运行版本或改变来源授权。
