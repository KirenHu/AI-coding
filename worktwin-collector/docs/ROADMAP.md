# 1.0 后续工作

1.0 已具备本地授权采集、知识演化和养护、Markdown 链接与历史、企业统一模型费用控制，以及持久共享快照和到期/撤销链接。产品保持三个入口。

当前首先完成编程工具动作与执行结果的归属：已有 Codex/Claude Code 工具名称、返回状态和有限退出码线索，但还缺少能安全处理敏感内容的原始执行结果、工作目录变化、续接关系和文件产物核验。当前提供用户明确创建/关联项目身份的跨来源合并；1.1.8 起优先让私有知识自动生效和迭代；下一重点是跨会话自动业务项目识别，依据直接命名、上下文关系、仓库与操作证据构造可解释的项目身份（不能仅凭同名或同目录）。证据不足就保持会话隔离并后台再分析，不让用户逐份确认。持续使用本人真实授权资料与当前模型评估采集覆盖、知识可用性、误合并、更新覆盖率、每百次变更的人工介入次数。

组织部署需要接入已有 SSO、成员目录与资料 ACL，增加身份验证的协作者访问；链接标签目前仅供本人管理。按组织要求完成代码签名/公证、密钥安全存储、安装策略、备份恢复、长期后台与唤醒验收。

1.1.9 已进入工作单元级项目关联、按来源/项目继承知识以及可选 Jev 判断模型的开发与回归阶段；后续应优先完善既有工作单元的自动重判与项目关系修复、分身批量规则迁移和权限追溯；其次完善浏览器插件经本地 CaptureSession 触发的 DOM 操作事件采集、持续评测、自主错误纠正与托盘体验。个人行为风格建模继续作为内部能力，不增加终端用户的复杂一级管理入口。


## 集成后仍需真实环境验证

流程平台上线后再配置可信 HTTPS Origin、签名服务及任务状态接口，完成真实 Chrome/Edge 网页覆盖率、事件摘要准确率、授权失效和任务结束测试。知识层需用多来源真实资料验证项目误合并及旧知识覆盖，不再增加默认逐条人工审核。
