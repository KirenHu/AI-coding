# 模型设置与 DeepSeek 实际验收（1.1.2）

打开「设置 → 个人版」，按下面填写：

| 字段 | DeepSeek 填写内容 |
| --- | --- |
| 模型服务地址 | `https://api.deepseek.com` |
| 模型名称 | `deepseek-flash` |
| API Key | 在 DeepSeek 开放平台创建的 API Key |

不要填网页地址、`/anthropic` 或 `/chat/completions`。模型列表可用于检查凭据和选择模型，但列表成功不等于对话调用成功。点击「测试连接并保存」，只有收到有效答案且密钥安全保存成功，才启用新配置。失败时保留先前配置，密钥输入框不被清空，便于修正后重试。

官方接口与模型名称：[DeepSeek 首次调用 API](https://api-docs.deepseek.com/zh-cn/)。DeepSeek 的 API 账户和网页聊天是不同的使用入口；HTTP 402 表示需要检查开放平台 API 余额。

## 本次真实模型验证

2026-10-09，使用用户明确授权的 Key，连接官方 `https://api.deepseek.com`，不经过本地模型替身。只发送临时示例资料，凭据不写入仓库、日志和安装包。临时加密凭据和测试数据库在测试结束后删除。

- 模型列表：实际返回 `deepseek-flash`、`deepseek-v4-pro`。
- 旧版测试请求复现：默认思考模式、`max_tokens=16`，实际返回 `finish_reason=length`、没有最终答案。不能把这类返回当作连接成功。
- 新版测试请求：明确关闭 DeepSeek 思考模式、测试预算 64，实际返回 `OK`。
- 通过 App 的个人配置 API，实际测试与加密保存成功。
- 授权并采集示例 Markdown，后台实际调用 DeepSeek 生成一篇带原文证据的知识：星河项目审批采用工作流节点配置。
- 确认知识并分配给示例分身，提问“星河项目为什么把审批配置为工作流节点？”；实际回答“目的是避免重复维护两套审批系统”，包含 `[K1]` 引用。
- 重启 App 后，从临时加密存储读取 Key，再次真实连接测试成功。

这证明该 Key、模型以及上述示例业务链路可用，不代表所有资料上的准确率已经评测。旧版截图同时有模型列表失败；列表请求不涉及思考预算，不能把它也归因于 16-token 问题。截图的旧版通用报错不足以确认用户 Mac 的证书、代理或钥匙串状态。

## 安装包与错误提示

安装包显式包含 certifi 的公共 CA 证书，保留系统证书信任、主机名校验和 HTTPS 校验。原生安装包验收要求从打包程序访问真实 DeepSeek `/models`，使用无效的示例凭据，并收到明确的 HTTP 401/403：无需真实 Key、不生成答案、不计费，验证 HTTPS 与错误反馈实际工作。

新版分别显示：HTTP 401 无效 Key、402 API 余额不足、403 权限或访问限制、404 模型或接口不存在、429 限流或额度、服务异常、证书验证失败、网络超时；连接成功但系统凭据存储失败也有单独提示。供应商响应原文和请求凭据不会出现在这些提示中。

升级前在左侧点击「退出」并确认，再替换「应用程序」中的 WorkTwin，重新打开。只关闭浏览器页面不会停止旧后台。已有资料和知识保留；模型密钥仍由本机钥匙串或凭据管理器保存。
