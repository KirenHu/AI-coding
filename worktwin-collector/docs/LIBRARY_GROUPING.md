# 知识库分组与文章维护（1.5.4）

项目描述持续的工作目标；分组描述研究对象、客户、产品或独立事项。例如“竞品调研”项目下可同时有 Orion、博洋。`knowledge.group_name/group_key` 独立于 `project/project_key`，不会创建数字分身授权。

## 处理路径

1. 文件和会话采集为原始资料，抽取有依据的材料。材料不作为知识库文章展示。
2. 文章路由读取已有文章全文和相关来源全文。同事项更新已有文章，独立的完整事项另建文章。
3. 写作读取原文；大原文分批继续维护完整草稿。独立审校检查证据、当前结论、可读性以及同项目其他文章的重复。审校不通过可修订一次，通过才发布。
4. 后台目录维护器读取项目内已授权文章全文，识别对象及别名，创建或沿用分组。没有新材料时也会检查现有目录；内容不变不会每轮重复调用。
5. 对同组内实质重复或共同解释同一事项的文章安排归并。商业评估、技术机制、不同业务任务可以保留独立文章，不按对象强制一篇。
6. 归并读取关联原文、重写并审校；保留一个文章 ID，其他文章进入归档，旧正文、历史与来源仍可查看。显式文章授权不同或用户手工维护的文章不自动合并。

## 用户界面

首页显示分组及未分组文章；分组显示名称、所属项目、文章数。点击进入，面包屑返回。搜索支持文章全文和组名。状态、类型、项目筛选保留。适用范围不再作为列表列显示；影响理解的适用条件仍在文章中，后台范围判断和来源授权照常执行。

“更多 → 整理任务”显示目录分组、文章归并的运行状态和失败原因，可以重试。模型配置测试成功后恢复失败任务，不重新提取已成功资料。

## 模型与验证

关键编辑阶段启用 DeepSeek/Qwen 思考，连接测试和普通抽取保留短请求。Qwen 使用 OpenAI 兼容接口，`enable_thinking=true`、`preserve_thinking=false`；每次编辑请求显式携带业务上下文，不依赖历史思考内容。

文章正文不再截取前 1,200 字。单次编辑上下文约 70 万字符上限；超过模型请求边界会明确失败，不静默丢弃原文。写作和证据审校支持分批。超大型目录的分层检索仍未实现，不把“扩大窗口”称为无限上下文。

浏览器文章继续由独立管线按网站和操作事项维护，本轮文件/会话目录归并器不处理浏览器证据。来源关闭 AI 使用后不进入目录模型；暂停采集而仍允许 AI 的历史资料可继续整理。

自动测试覆盖完整正文归组、无新材料归并、版本历史、并发变更、授权隔离及模型参数。真实模型评估脚本 `scripts/evaluate_library_organization.py` 仅使用合成数据，读取现有连接设置，不读取真实文档。2026-10-13 首次调用遇到 DeepSeek HTTP 402，尚未得到真实模型语义效果结论。

Qwen 参数依据：[百炼深度思考](https://help.aliyun.com/zh/model-studio/deep-thinking/)、[Chat Completions 参数](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions/)。既有维护机制的开源学习依据见 [KNOWLEDGE_EDITOR_RESEARCH.md](KNOWLEDGE_EDITOR_RESEARCH.md)。


## 1.5.5 并行调度

资料提取独立运行；目录分组、已有文章归并、文章维护在另一条线程按此顺序执行。模型运行时最多同时发送两个请求，原有推理及上下文配置不变。没有变化的文章签名不重复请求模型；一次处理读取整个项目现有文章，因此同一批变化合并处理。

写作与归并共用项目租约，长任务每分钟续租。目录分组采用独立租约和提交时签名校验，不改正文和授权；文章编辑或来源授权变化会使结果作废并重新排队。崩溃后继续沿用租约超时恢复，不抢占仍在运行的请求。

知识库每五秒检查状态和文章版本、分组变化。详情打开或有未保存内容时只提示更新，关闭后刷新列表。分类不等待提取队列清空。当前仅一个编辑通道，跨项目编辑不额外并发。


## 1.5.6 授权入口与分组导航

来源 `allow_ai` 同时约束模型整理和分身回答，不等同于采集开关，也不等同于分身自身的文章授权。原“AI 整理”标签无法表达完整影响，统一改为“AI 使用”，注明文本会发送至当前配置的模型。文章详情与分身选文列表提供“来源授权”入口，按实际引用来源显示名称、路径和开关。仅用户操作开关才改变授权；不会因为文章已生成而绕过来源权限。授权变化计入知识库刷新签名。

按 mingdao-design 的导航层级、工具栏和间距规则审查后，路径只保留实际浏览层级“知识库 / 分组”，项目通过项目筛选及分组摘要表达。目录导航和后台处理状态置于同一独立行，左侧导航、右侧次要状态，上方间距 24px、下方 16px；没有内容时整行隐藏。
