# 1.5.1 项目当前文档

1.5.0 仍让模型自由选题，旧条目的标题和摘要容易成为文章边界；项目会议资料又落在多个会话范围中，导致同一项目内容被拆散。原文补充检索会读取整个关联文件，旧讨论可能重新进入回答。

此次改变文章边界，而非只扩写或减少条目：同一项目默认维护一份当前文档。材料的主题成为章节，新会议和新规则更新原 ID，旧分篇归档。人工创建文章仍保留；后台自动生成不按字段、参数、单个决策或会议发言新增文章。

编写读取完整来源，并参考项目索引明确关联的现行基线。依据确认状态、覆盖关系和具体对象校正旧说法，文件修改时间不代表决策生效时间。阶段进展不能当永久规则；后续方向与现行规则分开表达。正文只展开影响理解、决策或执行的信息，细节与低价值讨论留在关联资料。

确实未定的事项在正文说明尚未确定，不同时给出两个互斥的当前口径；这不会让其余已确定知识全部失效。没有形成可读内容时留作材料，已经完成的当前文档与来源 AI 授权分别表示。

数据库用 project_documents 保存每个项目的当前文章 ID，article_current_sources 保存被选为当前依据的原文及内容指纹。模型选择来源片段 ID，程序保留原文，避免重新抄写引文时产生误差。旧证据留为历史；来源改动后，旧指纹退出默认检索，等待文章校正。

默认知识搜索只返回当前文章，不返回材料或原文。原始资料可显式请求 include_sources；MCP 的 search_article_sources 默认检索当前依据，include_history=true 才读取历史原文，结果标明其性质。完整日志授权继续独立检查。

历史重整在私有快照中限定文章和来源文档，补充明确关联的当前基线；不启动全量提取，不改变来源许可。审阅完成后只回写文章、依据和处理进度，保留正在采集的原始数据。私人编辑试稿在回写前折叠为一次实质更新，避免日志出现没有交付给用户的中间稿。

验收覆盖同项目不同会议与主题沿用一份文章、旧分篇退出默认搜索与分身、历史原文仍可显式查阅、来源变化后停止使用旧当前依据、ID 与授权保持、快照进度回写。真实项目资料另在本机副本中检查正文可读性与新旧口径。

阅读界面正文前只展示最近一次更新，完整版本从右上角日志进入。Markdown 表格按表格渲染；当前依据与历史引用分别折叠，旧材料不冒充当前正文。
