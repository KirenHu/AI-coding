# 数字分身 MCP

让其他 AI 在你授权的范围内读取 WorkTwin 知识，减少重复提供背景。MCP 是 AI 客户端连接外部工具和资料的协议；这里提供只读知识访问，WorkTwin 不会再调用自己的问答模型生成一遍答案。

## 连接步骤

1. 打开「数字分身」，选择分身，设置并保存它可用的知识范围。
2. 在「连接其他 AI（MCP）」中点击「启用并获取连接配置」。
3. 选择 Cursor、VS Code 或 Claude Desktop，复制配置，或点击「一键配置」。一键配置保留已有其他连接，并备份原配置文件。
4. 点击「测试连接」，配置完成后重启对应客户端，并保持 WorkTwin 运行。
5. 在客户端询问授权资料中的问题，核对读取的文章与引用。

Cursor 和 VS Code 使用本机 HTTP 连接；Claude Desktop 使用包内 stdio 桥接，不需要另装 Node.js。其他支持 Streamable HTTP 的 MCP 客户端可以手动配置。界面测试通过表示 WorkTwin 连接可用，不等于所有客户端版本均已验收。

默认只读有效知识和必要引用。确实需要整份来源资料或会话时，才在分身中单独开启完整日志授权。

更新连接凭据会立即使旧凭据失效。关闭 MCP、删除分身、撤销知识或日志授权立即生效；不需要复制、发布或重新同步一套权限。

## 授权与工具

- `list_projects`：仅统计该分身当前可用知识的范围。
- `search_knowledge`：按项目检索；未指定项目时只搜索通用知识，先列项目再选择，避免局部规则跨项目使用。
- `read_knowledge`：读取当前正文与当前必要引用，不提供历史正文或完整日志。
- `read_source_log`：仅在单独授权完整日志后可用，只读取当前可用、已授权知识引用的来源，分页最多 12,000 字符。

完整来源可能包含该文件或会话中的其他讨论，界面在授权时明确说明。来源 AI 权限撤销后停止提供知识与日志。凭据仅在创建时显示，数据库只存摘要；它不是供应商模型 Key，也不是本地管理令牌。

当前为本机预配置 Bearer 凭据连接，不提供云端 OAuth 登录。不同 AI 工具的配置界面和支持范围分别验收；官方客户端测试不等同于已完成 Codex / Claude Code 打包版本接入。

## 验证依据

`tests/test_twin_mcp.py` 用官方客户端对真实应用完成初始化、列工具与读取，检查知识隔离、停用、关闭 MCP、来源撤权及完整日志单独授权。`scripts/ui_mcp_acceptance.py` 验证生成配置、日志开关、关闭连接及未保存知识授权保护。
