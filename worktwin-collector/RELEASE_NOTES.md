# WorkTwin Collector 1.1.4 · 知识范围约束、Obsidian 增强与交互优化

- **知识范围与质量约束**：新增 Scoped Knowledge 机制，将知识按项目、讨论和全局范围划分，提炼时严格区分用户决策、AI 建议与用户验收，过滤低价值口头噪音。
- **分身防越权问答**：提问时自动识别或手动指定项目范围；多项目模糊提问时主动防御，提示选择范围，防止跨项目知识污染。
- **Obsidian 属性导出**：导出 Markdown Wiki 时注入标准 YAML Frontmatter 属性（包含 ID、标题、别名、状态、项目、主题、AI 适用性等），全面兼容 Obsidian 属性面板。
- **跨平台与底层修复**：
  - 修复 macOS 符号链接与临时目录（`/var` -> `/private/var`）导致文件扫描被跳过的问题。
  - 修复非 Linux 平台测试用例对凭据文件的断言异常。
- **前端交互体验提升**：
  - 知识库操作与编辑后自动保持当前滚动位置，告别回跳顶部。
  - 分身配置面板支持按项目“一键全选本组 / 取消”与“仅看已选”快速过滤。
  - 编辑抽屉支持 `Cmd+S` / `Ctrl+S` 快捷保存。
  - 分身问答增加平滑加载等待动画；信息采集页面新增后台任务自动轮询。

# WorkTwin Collector 1.1.3 · 模型连接修复与采集文案统一

- 采集入口、授权列表与默认名称统一为“本地文件夹”“Codex”“Claude Code”。旧默认名称按新文案显示，用户自定义名称保留；Codex 当前采集范围仍明确说明为会话。
- 为安装包包含独立的公共 CA 证书，保留系统证书信任与 HTTPS 校验，避免依赖打包机器的证书路径。
- DeepSeek 请求明确关闭默认思考模式，连接测试输出预算从 16 提升到 64；拒绝把空答案、思考内容或截断回答判为成功。个人与企业供应商调用保持一致。
- 模型列表和连接测试显示明确失败阶段：无效 Key、余额不足、权限拒绝、接口或模型不存在、限流、证书、网络超时、密钥保存失败。错误中不输出密钥或供应商响应原文。
- 使用用户授权的 DeepSeek Key 通过真实模型列表、测试保存、知识生成、带引用问答与重启后的连接测试；使用独立临时示例资料，凭据不进入源码或发行文件。

- 修复升级后浏览器复用旧脚本导致设置页一直加载：页面资源使用内容版本地址，并禁止保留旧缓存。
- 分身配置保存期间暂停编辑，并在分享信息读取前绑定编辑事件，避免快速继续编辑时丢失输入。
- 启动时校验界面与后台版本；若旧程序仍在后台运行，明确指导退出并重新打开。备份目录信息暂时不可用时，保留模型设置表单。

- 新增设置入口：个人配置模型地址、名称和 API Key；企业员工连接企业服务和企业 Token；管理员在同页管理企业模型、调用限额与员工授权。
- 可以获取服务商模型列表，也可手动填写；模型通过真实调用验证后保存。macOS 使用系统钥匙串，Windows 使用凭据管理器；企业供应商密钥只在服务端保存。旧客户端数据库中的企业 Token 会迁移并清除。
- 显示 AI 排队、处理中、失败和重试。知识支持状态筛选、归档恢复和个人偏好管理。
- 统一知识准入：未确认、待核对、已归档或来源权限失效的知识不能供分身使用；发布额外要求来源分享授权。显示数量与排除原因。
- 分身基本信息和知识授权一并保存，编辑保护与失败反馈更明确。支持本次会话的聊天记录、Enter 提问和可打开的知识引用。
- 可试问服务端当前发布版本。分享页刷新后继续访问，引用限定在当前分享范围；撤销员工 Token 同时停止其分享链接。
- 设置页提供 Markdown Wiki 导出及不含配置密钥的数据库备份。

## 升级与验收

退出旧版，再替换应用。数据目录不变，原有资料和知识会保留。此前 AI 自动生成但未确认的草稿需要先核对，才能用于分身。已配置的模型在重新启动后显示“已配置、尚未测试”，点击测试可验证当前连接。

DeepSeek 填写与实际验收见 [模型设置](docs/MODEL_SETUP.md)。

个人使用：打开「设置 → 个人版」，填写模型服务商提供的接口根地址、模型名称、API Key，点击「测试连接并保存」。企业使用：打开「设置 → 企业版」，使用管理员提供的地址和企业 Token。管理员部署说明见 docs/DEPLOY.md，一期边界见 docs/PHASE1.md。

发布检查覆盖真实 HTTP、SQLite、合成问答、四组浏览器操作及三个平台安装包启动。验收结果以对应 GitHub Actions 为准。付费模型已完成上述示例链路验证，尚未覆盖广泛资料上的准确率评测；组织 SSO/DLP、长期睡眠唤醒和物理设备弹窗仍需实际环境验收。

Apple Developer ID 签名与公证尚未完成，macOS 仍为 ad-hoc 签名测试包。保留原有 DMG 完整性、签名封装和原生启动检查。远程服务断开时权限修改可能尚未同步，服务器仍保留上次快照；访问链接持有人可以访问，收件人备注不构成身份验证。
