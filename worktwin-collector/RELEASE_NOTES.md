# WorkTwin Collector 1.2.0 · 任务触发式浏览器行为采集

在不改变用户正常业务跳转的前提下，新增可单独开启的浏览器操作采集。浏览器采集与文件夹、Codex、Claude Code 并列，默认关闭；插件安装并不自动授予采集或 AI 分析权限。

## 新增能力

- WorkTwin「信息采集」新增浏览器功能开关、独立 AI 分析授权、插件握手状态、最近任务及操作轨迹。
- 可从 WorkTwin 下载 Chrome/Edge 扩展 ZIP，解压后通过开发者模式手动加载；首次启用会出现安装/配对引导。插件通过主动握手确认可用，不声称能通用识别系统默认浏览器中安装了哪些扩展。
- 可信流程平台通过后端 Ed25519 签名生成一次性开始/完成信号；流程网页在用户点击原生业务链接时并行发送信号，不由 WorkTwin 或插件接管、重定向或重新打开链接。
- 流程平台信号动态指定当前任务的初始 HTTPS 页面；平台无权绕过浏览器本身的扩展访问权限。插件只有成功绑定指定标签页与文档后才观察 DOM，其他日常网页不监控、不上传事件。
- 记录用户点击、表单变化发生、提交、页面状态反馈及导航意图，事件按序入库，形成可追溯的观察步骤；不采集输入值、密码、原始 DOM、视频、浏览器历史。用户还可在 WorkTwin 导出 Markdown 轨迹或删除整次记录。
- 目标页刷新、跨域/同域跳转、SPA 路由变化等均停止后续网页监控，并记录导航。任务状态不会因此自动变成完成；仅可信流程平台相同任务及员工身份的签名完成信号可结束业务任务。另有最大采集会话时效限制。
- 独立授权后可依据脱敏操作步骤进行增量 AI 总结，仅标记为未验收的阶段分析；不自动写入当前有效知识，不改变既有数字分身、知识版本、证据及 MCP 授权规则。

## 验证与已知限制

- 后端签名/时效/nonce 防重放、范围匹配、标签页/文档绑定、事件幂等、导航停止、撤权、AI 单独授权、导出删除及 ZIP 随安装包分发均加入测试。
- CI 新增真实 Chromium 扩展 + 两个 HTTPS 测试网站 + 本地 WorkTwin 服务的端到端测试，验证原生新标签页/同标签页跳转、行为记录、跳转停止及任务完成信号。实际测试结果以 [PR #20](https://github.com/KirenHu/AI-coding/pull/20) 的 GitHub Actions 为准。
- **仍需实际企业流程平台联调和用户设备验证**：真实签名服务、公钥部署、浏览器权限提示、插件正式商店分发、不同系统的实际默认浏览器情况以及更多复杂网站场景。初版仅支持 Chrome/Edge，跨 frame、Canvas、原生系统对话框等无法保证完整采集。
- 浏览器操作步骤尚未自动提升为现有可引用的有效知识，只有通过独立的证据归属、知识准入、撤权闭环后才能增加这一能力。
- 正式 Apple Developer ID 签名/公证仍按用户决定暂停；macOS DMG 保持明确标识的未公证预览包。不要将原生 CI 打包通过等同于真实物理机器首次启动验收。

## 升级和接入

关闭旧 WorkTwin 后替换应用；原有数据库、分身权限与模型配置保留，新增浏览器采集默认关闭。流程平台的签名协议、Chrome/Edge 插件手动安装路径、隐私边界见 [任务触发式浏览器行为采集文档](docs/BROWSER_CAPTURE.md)。不要把未经授权的环境或真实用户数据用于验收。
