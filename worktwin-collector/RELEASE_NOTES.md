# WorkTwin 1.5.3 — 文件采集状态与大文件处理

- 文件状态区分“超过大小限制”“解析失败”“无法读取”“未提取到文字”，点击查看具体文件与原因。
- 点击超限数量后，展示文件名、大小和“处理这些文件”；仅本次所列文件放开 8 MB 上限，不修改全局限制或来源授权。
- 成功采集的大文件不重复提示；文件修改后重新判断。暂停的来源支持本次手动处理，仍保持暂停。
- 升级仅根据文件元数据纠正旧版超限误报，不主动导入超限文件。

# WorkTwin 1.5.2 — 基于现有开源机制的文章维护

- 借鉴 Rowboat 的目录识别与全文整理，取消“每项目固定一篇”；同事项更新原文章，独立事项可以分篇。
- 借鉴 Letta Code explicit integration：先生成候选，再独立核验原始证据、现行口径、必要背景和可读性；可自动修订一次，通过后才发布。
- 发布与材料回执同事务；拒绝不覆盖旧文、不消费材料。等待背景与审校失败分开处理，旧等待材料不会堵住新资料。
- 保留来源许可、稳定文章 ID、历史与当前引用。升级不重跑已处理资料，不人工归并历史项目。
- 新机制本轮接入文件与会话文章维护器；浏览器任务采集和网站文章管线保持独立。
- 研究源码、取舍与验证见 [改造依据](docs/KNOWLEDGE_EDITOR_RESEARCH.md)。

# WorkTwin 1.5.1 — 项目当前文档

- 同一项目的会议、决策和规则维护一份当前文档；新信息改写其中的章节，不再由模型自由拆成小文章。
- 编写时读取完整原文及明确关联的现行基线，先筛选内容价值，再整理当前方案。过时状态、重复细则和低价值讨论保留在来源。
- 默认搜索只返回当前文章，后台材料和原始记录退出默认结果。数字分身默认检索正文及被选为当前依据的引文；历史原文通过显式入口单独检索。
- 保留文章 ID、旧正文、版本及原始资料；项目归并的完成进度同步到本机，来源开关不变。
- 正文渲染 Markdown 表格；正文前只显示最近一次更新，完整版本保留在日志入口；当前依据与历史引用分别呈现。

# WorkTwin 1.5.0 — 材料采集与文章维护（本机测试版）

- 采集与编写分离：提取结果作为后台材料，周期性 Agent 根据项目和完整事项维护文章。
- 新信息只触发相关主题更新；读取原文上下文、保留当前结论，支持重排全文与合并重复文章。
- 项目归属积累持续目标和来源背景；AI 暂停时保留已有有效归属，证据失效时重新判断。
- 文章详情依次展示概要、实质更新记录、正文及来源依据；概要可编辑，历史可查看和恢复。
- 浏览器操作独立按具体事项整理；持续记录期间也可整理已有观察，同网站不同任务分篇并关联引用事件。
- 保留数字分身文章授权和来源权限。升级前备份数据库；历史重整通过独立副本验收后应用，不替换正在采集的原始资料。
- 文章维护的排队、失败及重试状态可见；旧版引用归入历史依据。macOS 钥匙串读取在后台执行，权限提示不会阻塞本地页面启动。

# WorkTwin 1.4.0 — 主题文章与新版工作台（测试候选）

- 一级导航改为知识库、数字分身、知识来源。知识详情以标题和正文为中心，变更历史从右上日志入口查看；编辑、回退、来源、关联与生命周期操作保留。
- 知识库默认展示主题文章，旧生成材料进入“待整理”。同批同主题的事实、步骤和决策可合为一篇，保留各条证据；后续更新沿用文章 ID 和历史，不通过最低字数制造长文。
- 数字分身试问改为连续对话，保留前文、每轮引用和新会话。知识或授权改变时开启新会话。删除单独排除功能，旧排除规则按当时可用集合转为逐条授权。

- 浏览器插件 0.4.0 以网站白名单和持续开关记录；总开关保留配对，任务与人工采集分别结束，各自证据保持隔离。
- 决策与路由模型放在主模型旁，说明其项目归属决策用途及轻量模型的成本作用。

升级只迁移组织状态及已明确替换的配置；不自动批量确认知识或重跑模型。1.3.x 升级前保存 `.pre-1.4.0.sqlite`，仍保留旧版本恢复点。本候选不安装覆盖本机应用、不合并 main、不发布正式 Release。

实现与验收边界见 [1.4.0 验收记录](docs/WORKBENCH_1_4_ACCEPTANCE.md)；SOP v2 回传和跨来源物理索引去重尚未完成，真实模型整理质量尚需实际资料验收。

# WorkTwin Collector 1.1.9 · 自动项目归属与分身授权继承

本版在 1.1.8 的自动知识维护基础上，新增 **工作单元级项目归属**、**动态分身授权**和 **可选高速判断模型**。当前属于 PR #21 开发草案，尚未发布或完成真实资料验收。

## 功能

- AI 按每个可提取工作单元识别业务项目，而不是强制把整份文档/会话归为一个项目；保留明确的来源证据、归属判断和历史记录。
- 已知项目候选先校验工作单元自身的仓库/PR 等身份证据，再可通过可选判断模型（Jev SystemOne 或 Chat Completions）判定项目一致性；没有配置时默认使用主模型。
- 项目未能可靠判明时保持会话范围，不创建人工确认负担，不通过推断扩大跨来源共享权限。
- 个人版单独安全配置判断模型；企业版管理员在服务器上统一设置，员工无需供应商 Key。
- 数字分身可以一次授予整个项目、来源或通用知识范围；新增知识自动继承。保留旧版逐条知识勾选，允许显式拒绝规则。
- 本地问答、只读 MCP 和远程发布共用授权决策；每次检查来源 AI 权限与分享权限。AI 项目关联不会自行增加任何数字分身授权。

## 尚未交付和限制

持续重判历史不确定项目、完整跨会话连续操作追踪、浏览器事件采集、复杂混合文档的段落级权限分割以及真实授权资料的规模化误合并评测仍待完成。Jev 支持依赖具体供应商提供的 `/v1/systemone` API；未提供供应商 Key，因此目前仅执行模拟客户端和协议测试，不能声明真实付费调用已验收。

# 1.4.1 测试候选

- 网站不记录的问题：应用升级不会同步升级已解压安装的浏览器插件。插件 0.4.1 上报版本和已获得的网站权限；工作台分别显示插件需升级、网站权限待授权、等待访问和采集中。插件授权提示优先对应当前标签页。
- 分身最小授权单位改为知识库文章，旧材料不再进入文章选择或问答范围。项目、来源授权自动包含文章，“补充授权文章”用于选择范围之外的文章；当前原始资料片段随文章供问答与 MCP 检索，远程分享仍需来源分享许可。
- 文件夹以目录名称显示，路径用于区分同名目录，添加时自动命名。
- 项目判断使用正文、文件夹/工作目录、文件时间、相邻已授权资料与已有项目；先识别稳定业务项目，再按完整工作事项聚合文章。目录或时间不单独决定归属，会议/字段/单个规则通常作为文章内部内容。项目决策沿用可选的决策与路由模型。

升级不自动开启来源 AI 授权，不安排全量私人资料重处理。已有文章需要在授权范围内重新整理才能采用新的项目归属与聚合结果。
