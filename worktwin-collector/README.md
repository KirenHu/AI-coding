# WorkTwin

**把日常工作，沉淀成你和 AI 都能继续使用的知识。**

WorkTwin 是一个 AI 驱动的个人知识数字分身工具。连接你授权的工作资料后，它会持续提取上下文、维护知识文章，并让数字分身在你指定的范围内回答问题。

你继续使用原来的工具工作，WorkTwin 负责把分散的记录整理成可以独立阅读的经验、规则和方法。每篇文章保留来源与版本，方便核对和修正。

## 为什么做 WorkTwin

工作经验往往散落在文档、对话和操作过程中。真正需要时，我们仍要回翻记录、判断哪条结论有效，再向同事或 AI 解释一遍背景。

WorkTwin 希望让这部分积累随工作持续发生：资料变化时，更新相关知识；结论有依据时，保留依据；需要复用时，只提供已授权的内容。它既保存工作线索，也把线索整理成面向读者的文章。

## 它能帮你做什么

| 你的需要 | WorkTwin 的做法 |
| --- | --- |
| 搞清一项需求现在采用什么方案 | 汇总相关资料，维护当前文章，保留决策背景与原文依据 |
| 减少重复整理项目经验 | 检测授权资料的新增和变化，更新相关主题，归并重复文章 |
| 复用经常执行的网站操作 | 用浏览器扩展记录脱敏操作事件，逐步整理成网站操作文章 |
| 让 AI 理解项目背景 | 将数字分身的授权知识通过只读 MCP 提供给其他 AI |
| 把部分经验分享给别人 | 创建不同分身、划定知识范围，按需生成远程访问链接 |

例如，某项审批规则先在会议中讨论，随后写入方案，之后又被正式修改。WorkTwin 会尝试识别它们的关联，把有依据的现行规则更新到原文章中，同时保留旧版本。模型判断仍可能出错，你可以查看依据、编辑正文或回退版本。

## 从工作记录到可复用的知识

1. **连接来源**：选择文件夹、编程助手或浏览器记录，分别决定是否采集、是否允许 AI 使用、是否允许分享。
2. **理解上下文**：结合工作目标、目录、会话关系等证据判断资料归属；证据不足时保留较小范围。
3. **持续维护文章**：文件和会话先形成材料，再经过选题、编写和独立审校，通过后更新知识库。相关新信息更新已有文章，独立事项可以分篇。
4. **阅读与修正**：按项目或对象分组查找文章，查看正文、来源和历史，必要时自己修改。
5. **授权复用**：分身按项目、来源或指定文章获取知识；符合授权规则的后续有效知识可以自动继承。

浏览器操作使用独立处理流程：个人记录可以形成操作文章；企业平台触发的任务记录不自动进入个人知识库。

## 可以连接哪些资料

| 来源 | 当前支持的内容 | 使用边界 |
| --- | --- | --- |
| 本地文件夹 | Markdown、TXT、代码、DOCX、可选中文字的 PDF | 只读取选定目录；扫描 PDF 暂无 OCR |
| Codex | 本机可识别的 JSONL 会话、可见消息与工具动作摘要 | 不含未落盘云端会话或隐藏推理 |
| Claude Code | 本地项目 JSONL 会话中的可见消息与工具摘要 | 不含 Claude Desktop 云端会话 |
| Cursor CLI | `stream-json` 导出的 JSONL | 不读取 Cursor IDE 私有聊天数据库 |
| Google Antigravity | 本地 `brain`、`knowledge` 中的 Markdown 成果 | 不含完整对话 |
| Chrome / Edge 扩展 | 授权网站的点击、导航等脱敏 DOM 操作事件 | 不录屏，不采集表单输入值、页面全文或跨源 iframe |

编程会话首次开启「AI 使用」后默认从新增记录开始整理；历史补录需在来源设置选择日期范围。成果文档仍通过文件夹来源连接。

## 开始使用

1. **安装并打开 WorkTwin**：从 [Releases](https://github.com/KirenHu/AI-coding/releases) 选择对应系统的包，或[从源码运行](docs/GETTING_STARTED.md#从源码运行)。请先核对下方版本说明。
2. **连接模型**：在设置中填写支持 OpenAI Chat Completions 接口的模型服务地址、模型名和 API Key，测试连接并保存。企业用户可连接管理员提供的服务。
3. **添加一个来源**：建议先选一个小型项目资料目录，并开启它的「AI 使用」。
4. **阅读第一篇文章**：在「知识库」查看处理结果和依据；在「数字分身」创建分身、授权文章并试问。

完整操作和常见问题见[入门指南](docs/GETTING_STARTED.md)。其他 AI 的接入见 [MCP 指南](docs/MCP.md)；远程分享需另行部署持续运行的[分享服务](docs/DEPLOY.md)。

## 数据由你决定如何使用

工作资料和知识库保存在本机。**本地保存不等于完全离线**：开启「AI 使用」后，相关文本会发送到你配置的模型服务，调用费用取决于该服务。

采集、AI 使用、分身访问和远程分享有各自的授权范围。远程发布上传获准的有效知识标题与正文，不上传原始文件或完整会话；本地 MCP 默认只读授权知识及必要引用，完整来源日志需要另行授权。

远程链接的持有者可以访问，链接也可能被转发。客户端离线时，远端保留上次同步的快照；退出客户端不会撤销已发布分身。具体授权、撤销、备份与存储位置见[数据与分享说明](docs/DATA_AND_SHARING.md)。

## 当前状态

本分支源码版本为 **1.5.9 测试版**。本文介绍本分支已实现的能力；截至 **2026-10-14**，GitHub 最新正式 Release 标签仍是 `worktwin-v1.1.7`，不能用旧安装包体验本文全部功能。

1.5.9 已有 macOS 签名、公证及本机安装验收记录，但尚未作为正式 Release 发布；Windows 测试产物仍未签名。具体证据和边界见 [1.5.9 交付记录](docs/P0_P1_DELIVERY_1_5_9.md)。下载、签名判断和升级步骤见[入门指南](docs/GETTING_STARTED.md)与 [macOS 安装说明](docs/MACOS_INSTALL.md)。

持续文章维护和授权流程已有自动化与部分真实模型验证。不同资料上的整体知识质量、长期运行效果和月度成本仍需持续评估；企业平台浏览器任务的真实联调及 SOP v2 尚未完成。
